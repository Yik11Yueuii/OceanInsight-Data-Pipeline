## Hadoop下载实测结论

不要使用 `archive.apache.org` 下载696MB主安装包：广州ECS实测可能只有约12KB/s。正式教程使用阿里云VPC内网镜像：

```bash
curl -fL --retry 3 \
  -o hadoop-3.3.6.tar.gz \
  http://mirrors.cloud.aliyuncs.com/apache/hadoop/core/hadoop-3.3.6/hadoop-3.3.6.tar.gz
```

SHA512小文件仍取Apache官方源。官方校验文件内部名称为 `hadoop-3.3.6-RC1.tar.gz`，而正式包名没有 `RC1`。不能直接执行普通的 `sha512sum -c`，正式校验命令为：

```bash
sed 's/hadoop-3.3.6-RC1.tar.gz/hadoop-3.3.6.tar.gz/' \
  hadoop-3.3.6.tar.gz.sha512 \
  | sha512sum -c -
```

唯一正确结果：

```text
hadoop-3.3.6.tar.gz: OK
```

### 正式教程必须预先规避的两个问题

1. HiveServer2不能把PID写入只允许root修改的 `/opt/hive/conf`。systemd服务必须预先设置：

   ```ini
   Environment=HIVESERVER2_PID_DIR=/data/oceaninsight/hive/pids
   Environment=HIVE_PID_DIR=/data/oceaninsight/hive/pids
   ```

2. 单机教学环境使用远程Metastore时，HiveServer2会读取通知事件接口。必须在 `hive-site.xml` 中设置兼容配置，否则服务进程虽然显示 `active`，却会每60秒重试且不监听10000端口：

   ```xml
   <property>
     <name>hive.metastore.event.db.notification.api.auth</name>
     <value>false</value>
   </property>
   ```

   是否启动成功必须同时用端口和SQL验证，不能只看systemd的 `active`：

   ```bash
   sudo ss -lntp | grep -E '9083|10000'
   beeline -u 'jdbc:hive2://127.0.0.1:10000/default' \
     -n ecs-user \
     -e 'SHOW DATABASES;'
   ```

SLF4J多绑定警告不会阻止本次Hive运行，正式教程注明后可忽略，不引导学生额外删除JAR。

## ECS重新启动后的恢复检查

2026-08-25实测发现：MariaDB、Hive Metastore和HiveServer2的systemd服务会显示为`active`，但HDFS的NameNode与DataNode不会自动恢复。此时HiveServer2进程可能存在，却不会监听10000端口，因为它无法连接HDFS。

恢复时只启动已有的NameNode和DataNode，绝对不能再次格式化NameNode：

```bash
hdfs --daemon start namenode
hdfs --daemon start datanode
sleep 5
jps
hdfs dfs -ls /oceaninsight
```

确认HDFS中的原有目录可以正常列出后，重启HiveServer2：

```bash
sudo systemctl restart oceaninsight-hiveserver2

for i in {1..12}; do
  if sudo ss -lntp | grep -q ':10000'; then
    echo 'HiveServer2 已启动'
    break
  fi
  echo "等待 HiveServer2：第 ${i}/12 次检查"
  sleep 10
done
```

最后必须同时检查进程、端口和SQL：

```bash
jps
sudo ss -lntp | grep -E ':(3306|9000|9083|10000)\b'
beeline -u 'jdbc:hive2://127.0.0.1:10000/default' \
  -n ecs-user \
  --silent=true \
  --showHeader=true \
  --outputformat=table \
  -e 'SHOW DATABASES;'
```

本次实测恢复成功后，`jps`显示NameNode、DataNode和两个Hive RunJar进程；3306、9000、9083、10000端口均正常监听。Hive中已确认以下数据库：

- `default`
- `ocean_ods`
- `ocean_dwd`
- `ocean_dws`
- `ocean_ads`

### 船舶主数据血缘字段修复与入湖

真实学生流程发现：学生源包内的船舶主数据已经带有`batch_id`和`source_file`，原筛选函数再次追加同名字段，造成输出表头和数据行均为26列。该问题来自程序对输入字段的错误假设，不是学生操作失误。

最终成功路线已修正为：生成输出字段时先排除输入中已有的两个血缘字段，再在末尾统一写入本次学生批次的`batch_id/source_file`。本地程序新增回归测试，确认已有血缘字段会被替换而不是重复追加；完整测试现为12项并全部通过。

服务器端保留错误文件备份，将正式CSV原子修复为24列，并同步更新Manifest字节数和SHA256。前一次DataX虽然报告149,660条、失败0条，但它按24列配置静默忽略了输入末尾多出的两列，因此该HDFS文件被精确删除后重新执行。重跑日志表头为24列，149,660条全部写入、失败0条；最终逐行验收确认24列异常、批次异常和源文件异常均为0。

最终傻瓜式主路线只采用修复后的24列生成方法；26列现象仅作为常见问题说明，并明确不是学生操作错误。

## 后台Spark任务的等待提示（学生必读）

执行DWD、DWS和ADS的`nohup spark-submit ... &`后，命令行立即显示`STARTED`只代表任务已经提交，不代表计算完成。学生第一次查看时很可能只看到Spark启动信息或如下阶段标题：

```text
===== 1/2 构建海洋月度网格DWS =====
```

这属于正常运行状态。海洋和船舶全量聚合包含大文件扫描、`GROUP BY`、Shuffle及去重统计，在4核8G服务器上需要等待数分钟。教程必须在启动命令正下方醒目标注：

1. 先等待约2—5分钟再检查，具体时间以实测为准；
2. 若PID仍在、没有错误标记，就继续等待；
3. 不要重复启动同一个脚本，不要手动删除Spark临时目录或目标表；
4. 只有看到对应的`...=PASS`才表示该阶段完成；
5. 浏览器可以断开，`nohup`任务仍会继续，重新连接后读取原PID和日志即可。

最终傻瓜式教程不得只在长段落末尾提及耗时，必须把这段等待说明紧跟在每个后台启动步骤之后。

## ADS备用CSV导出实测

第一次导出时，Spark写出路径使用了未带协议的绝对路径。由于服务器默认文件系统是HDFS，Spark实际把第一张CSV写到了HDFS中的`/home/ecs-user/.../ads_csv_stage`，而随后Python使用本地`pathlib`查找分片，因此报告“未生成唯一CSV分片”。这不是学生操作错误，也没有影响7张Hive ADS表。

## MariaDB ADS建表关键字排错

MariaDB发布前检查确认服务正常，`ads-db.cnf`权限为600，`ads_writer@localhost`可连接MariaDB 10.6.25，并找到MySQL Connector/J 8.4.0。首次创建总览表时报语法错误；字节级检查证明SQL文件没有反斜杠，普通下划线也没有被污染。真实原因是`YEAR_MONTH`属于MariaDB时间间隔关键字，作为列名必须使用反引号引用。

修正版DDL将字段及复合主键中的该列统一写作反引号引用的`year_month`。实测`MARIADB_OVERVIEW_DDL_EXIT=0`，成功创建9字段的`ads_ocean_overview`，复合主键为`scope_type/year_month`，`refreshed_at`默认当前时间。最终文档不得把该问题错误归因于学生复制操作；MariaDB所有ADS DDL都必须引用`year_month`列。

使用MySQL Connector/J 8.4.0进行Spark JDBC单表试发布。Spark程序从权限600的`ads-db.cnf`读取连接参数，日志和命令行均不展示密码。总览表实测发布结果：

```text

SPARK_JDBC_OVERVIEW_WRITE=PASS
MariaDB行数=61
MariaDB唯一键=61
批次数=1
批次=student-ads-20260825
```

MariaDB样例同时显示整体3,357,840条输入、2,687,015条有效记录、有效率约0.80022，以及60个月度记录和统一刷新时间，证明Hive ADS到MariaDB的JDBC链路与字段映射正确。
